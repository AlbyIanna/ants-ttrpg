FOLDER MAPPING:
══════════════
/rules/         → rule_schemas       (JSON definitions)
/sims/          → simulation_engine, rule_engine, event_manager, 
                  agent_orchestrator, session_runner, memory_logger (JS modules)
/narrative/     → narrative_templates (JSON content)
/prompts/       → prompt_templates   (JSON templates)
/tests/         → Unit tests & integration tests

KEY DEPENDENCIES:
════════════════
• session_runner depends on: simulation_engine, agent_orchestrator, memory_logger
• simulation_engine depends on: rule_engine, event_manager
• rule_engine depends on: rule_schemas
• event_manager depends on: narrative_templates, rule_schemas
• agent_orchestrator depends on: prompt_templates

DESIGN PRINCIPLES:
═════════════════
• Modular: Each component has single responsibility
• Layered: Clear separation between orchestration, logic, and data
• Testable: Interfaces allow unit testing of individual modules
• Extensible: New rules, events, narratives can be added via JSON
• Swarm Intelligence: Architecture supports emergent behaviors from simple rules
